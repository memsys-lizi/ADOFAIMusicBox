# ADOFAI Music Box 项目总结

## 1. 项目定位

ADOFAI Music Box 是一个 Windows 本地 ADOFAI 谱面音乐播放器，使用 Tauri + React + TypeScript 实现前端界面，Rust 负责本地文件扫描、谱面解析、资源路径解析、曲库缓存和音频时间线生成。

它不是普通的音乐播放器，也不是 ADOFAI 游戏本体复刻。核心目标是：以 `.adofai` 谱面文件为音乐入口，读取谱面所在文件夹里的音乐、封面、小图标、视频和元数据，并在播放音乐时实时播放与谱面严格对齐的打拍音、三球音效、长按音效和 PlaySound 音效。

## 2. 当前已经实现的主要功能

### 2.1 本地曲库

- 支持添加本地文件夹，自动扫描文件夹下的 `.adofai` 谱面。
- 支持单独添加一个 `.adofai` 文件作为单曲来源。
- 支持管理本地来源，包括文件夹、单曲来源、已移除曲目恢复。
- 支持手动从曲库移除歌曲。
- 文件夹扫描出来的曲目如果被手动移除，会记录到隐藏列表，后续重新扫描不会自动回来。
- 支持喜欢、最近播放、本地三个主入口。
- 支持列表视图和网格视图。
- 支持搜索、排序、定位到当前播放曲目。
- 没有解析到封面和小图标时，使用默认资源：
  - 小图标：`src/assets/icon.jpg`
  - 封面：`src/assets/header.jpg`

### 2.2 ADOFAI 谱面解析

- 支持标准 JSON 谱面。
- 支持部分非标准 `.adofai` 文件的宽松解析。
- 处理了谱面里常见的 Unity 富文本标签，例如 `<color>`、`<size>`、`<b>` 等，前端展示时会清理成普通文本。
- 会读取主要 settings 元数据：
  - 曲名
  - 艺术家 / 作曲
  - 谱师
  - BPM
  - 音乐文件
  - 封面
  - 小图标
  - 视频文件
  - 视频偏移
  - 音量和音效相关设置
- 会忽略部分教程关卡或明显不是主关卡的谱面，减少曲库里出现无法播放的 `main` 垃圾项。

### 2.3 播放器

- 使用 Web Audio API 播放主音乐。
- 使用 lookahead scheduler 提前调度短音效，保证打拍音不会依赖 React 渲染时机。
- 支持播放 / 暂停 / 上一曲 / 下一曲。
- 支持进度条拖动。
- 支持顺序播放、列表循环、单曲循环、随机播放。
- 支持音乐音量、打拍音量、谱面音效音量调节。
- 点击歌曲行会立刻切歌并播放。
- 点击底部封面进入沉浸播放页。

### 2.4 打拍音和谱面音效

当前音乐时间线已经按 ADOFAI 源码思路迁移了音乐播放相关部分，重点处理：

- `angleData` / `pathData` 生成地板序列。
- `SetSpeed` 改变后续地板间隔。
- `Twirl` 改变旋转方向。
- `Pause` / `FreeRoam` 增加额外等待时间。
- `SetHitsound` 改变后续普通地板打拍音。
- `PlaySound` 播放谱面或内置短音效。
- `MultiPlanet` / 三球 DLC 相关节拍处理。
- `Midspin` 中旋地板处理。
- `Hold` / `SetHoldSound` 长按开始、循环、结束音效。
- 三球激活音效和对应地板音效同一时间点播放，而不是先后错开。

### 2.5 视频背景

- 支持带视频资源的谱面在沉浸播放页显示视频背景。
- 视频会跟随音频播放、暂停和拖动进度。
- 视频同步使用谱面内的视频偏移配置。
- 修复过视频慢一拍、黑屏闪一下、重新进入详情页才出现视频等观感问题。
- 对有视频的谱面，详情页可以切换视频背景开关。
- 有视频时，唱片区域可以隐藏，谱面信息默认偏折叠展示。

### 2.6 QQ 音乐风格 UI

界面已经从早期黑白灰工具感，改造成 QQ 音乐 Windows 客户端方向：

- 浅色主界面。
- 左侧导航。
- 顶部搜索。
- 本地曲库主体。
- 底部固定播放控制栏。
- 圆角、浅灰分区、宽松留白。
- 点击封面进入沉浸播放页。
- 沉浸页背景色会根据封面提取主色，生成柔和背景。
- 沉浸页左侧是唱片机视觉，唱片播放时旋转。
- 控制按钮、进度条、音量条等尽量跟随当前封面强调色。
- 禁止在 UI 中出现面向开发者的词，例如 parse、debug、timeline、resourceStatus 等。

### 2.7 Tauri 桌面体验

- 使用无系统边框窗口。
- 自绘最小化、最大化、关闭按钮。
- 修复窗口拖动区域不稳定的问题。
- 禁止文字和图片被选中，避免操作时出现蓝色选区。
- 禁止系统默认右键菜单，使用自定义曲目右键菜单。
- 曲目右键支持打开源文件位置、移除等操作。
- 配置了 opener 权限，解决打开文件夹时报 `opener.open_path not allowed` 的问题。

### 2.8 启动性能

之前软件启动慢的主要原因是：Tauri 启动阶段同步扫描并解析整个曲库，窗口显示前就被大量 `.adofai` 文件拖住。

目前已经改成：

- 启动时只读取设置和曲库缓存。
- 曲库扫描结果保存到本地 `tracks.json`。
- 没有缓存时先打开界面，再后台扫描。
- 手动重新扫描在后台线程执行，避免卡住界面。
- 添加单曲、移除曲目、移除来源时，会同步更新曲库缓存。

第一次启动或清空缓存后仍然需要扫描一次，但后续启动应明显更快。

## 3. 采过的坑和解决方式

### 3.1 `.adofai` 不一定是标准 JSON

很多谱面文件不是严格 JSON，可能有 BOM、尾逗号、奇怪空白、注释、换行控制字符，甚至字符串里带非法换行。

解决方式：

- 标准解析失败后走宽松解析。
- 前端不直接暴露底层解析错误，统一展示普通用户能理解的话。
- 对彻底无法修复的谱面，不让它污染播放流程。

### 3.2 谱面名和作者名里有富文本标签

很多谱师喜欢在标题、艺术家、谱师字段里写 Unity 富文本，例如：

```text
<color=#00A2FF>R</color>
<size=65>...</size>
```

一开始这些标签直接显示在列表里，非常难看。

解决方式：

- 前端统一用 `cleanDisplayText` 清理显示文本。
- 曲库、底部播放器、详情页都展示清理后的普通文本。

### 3.3 打拍音不能简单按 BPM 等分

ADOFAI 的打拍时间不是简单的 `60 / BPM`。实际会受到很多事件影响：

- 角度变化。
- 旋转方向。
- `SetSpeed`。
- `Twirl`。
- `Pause`。
- `FreeRoam`。
- 中旋。
- 三球。
- 长按。

早期如果只按 BPM 或地板数量排音，会在复杂谱面里全部错位。

解决方式：

- 按地板序列构建时间线。
- 每个地板根据角度、方向、速度和事件累计真实时间。
- 中旋、三球、暂停、自由移动都参与时间计算。

### 3.4 中旋谱面会导致后续全部错乱

有中旋的谱面里，部分砖块不应该按普通地板节奏处理。如果把中旋也当成普通地板，后面的时间会越来越偏。

解决方式：

- 单独识别 `Midspin`。
- 中旋的音效和普通地板音效分开处理。
- 中旋不会错误推进普通地板节奏。

### 3.5 三球 DLC 音效必须和地板音效同点播放

三球部分一开始出现过“先播放激活三球音效，再播放地板音效”的问题，听起来像晚了一个拍子。

真实逻辑应该是三球激活音效和该地板本身音效在同一个时间点触发。

解决方式：

- 三球激活音效作为同一时间点的额外事件加入。
- 不让它占用或推迟普通地板音效时间。
- 修复后 `Light Years Away` 这类三球谱面不再从 1:08 附近开始乱掉。

### 3.6 长按音效不是普通打拍音

长按需要开始、循环、结束三类声音，且可能受 `SetHoldSound` 影响。早期播放器没有正确播放长按音效。

解决方式：

- 加入 `Hold` 事件解析。
- 加入 `SetHoldSound` 状态。
- 默认长按音效使用 ADOFAI 的 Fuse 逻辑。
- 长按中段循环音效按照谱面持续时间生成。

### 3.7 Web Audio 有延迟，不能点击时才播短音效

如果到点才创建并播放短音效，浏览器调度和主线程抖动会让打拍音晚一点。

解决方式：

- 用 AudioContext 时间作为主时钟。
- 播放时建立音乐开始时间和谱面时间的映射。
- 用 lookahead scheduler 提前把即将发生的音效 schedule 到 Web Audio。
- 暂停、恢复、拖动进度时重新计算调度窗口。

### 3.8 音乐、打拍音、谱面音效音量不是一个东西

这里分成三类：

- 音乐：主音频文件。
- 打拍音：地板命中音，例如 Kick、Hat、Clack、三球等。
- 谱面音效：`PlaySound` 触发的额外音效，可能是内置音效，也可能是谱面文件夹里的外部音效。

一开始音量 UI 有了，但打拍音和谱面音效没有真正接到各自 GainNode。

解决方式：

- 主音乐、打拍音、PlaySound 分别接独立音量。
- UI 调节直接影响对应音频通道。

### 3.9 视频同步不能乱套公式

视频谱面有自己的 `videoOffset`。不同谱面的视频偏移方向不能凭感觉统一改。

采坑情况：

- `ViLLAGE OF CHRYSANTHEMUM` 一开始视频和音乐没对齐。
- 修改后又导致另一个原本正常的 `2129766036/main.adofai` 视频变慢。

解决方式：

- 不做全局硬编码补偿。
- 使用谱面自身 `videoOffset`。
- 视频时间根据当前音乐时间、pitch、song offset 和 video offset 计算。
- 避免为了一个谱面修坏另一个谱面。

### 3.10 视频详情页返回后再进入会黑屏一下

如果退出详情页就卸载 video 元素，再进入时视频需要重新加载，观感上会黑一下。

解决方式：

- 对有视频的当前曲目，详情页关闭时让视频组件保留在不可见状态。
- 再次进入时直接显示已有视频，不重新从零加载。

### 3.11 小封面转场残影

进入沉浸详情页时，底部小封面曾经会等动画结束才消失，看起来像多出一个封面。

解决方式：

- 去掉不合适的 View Transition 绑定。
- 用更直接的显隐状态和 CSS 动效控制。

### 3.12 曲库手动移除不能只改当前列表

如果用户从文件夹扫描出来的曲目里手动移除一首，但只在前端临时删除，下一次重新扫描它就会回来。

解决方式：

- 对文件夹来源曲目，手动移除后写入 `hiddenTracks`。
- 扫描时过滤隐藏曲目。
- 管理本地来源里提供恢复入口。
- 单曲来源移除时，从 `adofaiFiles` 删除。

### 3.13 添加单曲不应该触发整库重扫

添加一个 `.adofai` 单曲如果每次都重新扫描整个 workshop 文件夹，体验很差。

解决方式：

- 添加单曲时只解析这一个文件生成 `TrackSummary`。
- 更新曲库列表和缓存。
- 不触发完整扫描。

### 3.14 启动阶段不能做重活

早期 `AppState::load()` 会直接扫描所有来源。曲库越大，软件双击后越久没反应。

解决方式：

- 启动只读设置和缓存。
- 扫描放后台。
- 手动扫描也放后台线程。

## 4. 当前主要文件结构

### 4.1 前端

- `src/App.tsx`：应用主状态、曲库、设置、播放、弹窗、来源管理串联。
- `src/components/AppShell.tsx`：应用外壳、左侧栏、顶部区域。
- `src/components/FolderManager.tsx`：本地来源管理。
- `src/features/library/LibraryView.tsx`：曲库列表和网格。
- `src/features/player/MiniPlayer.tsx`：底部播放器。
- `src/features/player/FullPlayerOverlay.tsx`：沉浸播放页、唱片、视频背景。
- `src/audio/useAdoAudio.ts`：Web Audio 播放和调度。
- `src/lib/tauri.ts`：前端调用 Tauri 命令。
- `src/lib/text.ts`：显示文本清理。
- `src/types/domain.ts`：前后端共享类型。
- `src/styles/*.css`：设计令牌、布局、曲库、播放器、弹窗样式。

### 4.2 Rust 后端

- `src-tauri/src/adofai/models.rs`：曲目、设置、时间线等数据结构。
- `src-tauri/src/adofai/parser.rs`：`.adofai` 解析。
- `src-tauri/src/adofai/scanner.rs`：本地扫描和资源识别。
- `src-tauri/src/adofai/timeline.rs`：ADOFAI 音频时间线生成。
- `src-tauri/src/adofai/settings.rs`：设置和曲库缓存读写。
- `src-tauri/src/adofai/commands.rs`：Tauri 命令入口。
- `src-tauri/src/lib.rs`：Tauri app 初始化和命令注册。

## 5. 本地数据

当前本地数据主要放在系统配置目录下的 `ADOFAI Music Box` 文件夹。

主要文件：

- `settings.json`：用户设置、本地来源、喜欢、最近播放、隐藏曲目等。
- `tracks.json`：曲库缓存，用于加快启动。

这样做的好处：

- 不污染谱面目录。
- 重新打开软件可以快速恢复曲库。
- 手动移除曲目不会因为重新扫描立刻回来。

## 7. 后续建议

### 7.1 启动体验继续优化

当前已经去掉启动同步扫描，但还可以继续做：

- 首屏骨架屏。
- 扫描进度显示。
- 曲库缓存版本号。
- 缓存增量更新。
- 后台只扫描新增或修改过的谱面。

### 7.2 音频兼容继续补齐

后续可以继续对照 ADOFAI 源码补更多边缘情况：

- 更多内置音效名称映射。
- 外部音效文件扩展名兜底。
- pitch、volume、offset 在更多事件里的交互。
- 更复杂的三球和特殊地板组合。

### 7.3 UI 继续靠近 QQ 音乐

当前主方向已经接近，但后续还能继续精修：

- 列表 hover 和选中状态更细腻。
- 底部控制栏动效继续顺滑。
- 沉浸页唱片机素材继续精修。
- 更多按钮浮层动画。
- 空状态和加载状态更精致。

### 7.4 曲库管理

可以考虑：

- 歌单功能。
- 批量移除。
- 批量恢复。
- 曲库去重规则可配置。
- 文件变动自动监听。

## 8. 一句话总结

这个软件现在已经从“能扫 ADOFAI 文件的播放器雏形”，变成了一个真正围绕 ADOFAI 谱面音乐体验设计的本地播放器：重点不只是播放音乐，而是把 ADOFAI 的打拍音、谱面音效、视频背景、封面资源和本地曲库管理都串成一个比较完整的桌面音乐软件。
